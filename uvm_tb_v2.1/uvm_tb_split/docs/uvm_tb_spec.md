## Agents
- **CPU agent (active):** item has id/we/addr/wdata/wstrb (+rdata/err). Driver = 2 threads (request, response), `get()` + `put(rsp)`, `max_outstanding` cfg (1 now, N for v2), random `cpu_rsp_ready`. Monitor pairs req/rsp by id.
- **Flush agent (separate, active):** drives only flush_req/flush_inv; holds until flush_busy, waits flush_done, reads flush_err. Separate so flush can race a pending CPU request.
- **Mem agent (reactive):** monitor → `uvm_tlm_analysis_fifo` in mem_seqr + scoreboard. `mem_resp_seq` forever: get req, random latency/err, read/write `mem_model` (no write on error). Driver = 2 threads (random `mem_req_ready` backpressure; responses after latency, hold until rsp_ready). Latency models DRAM/beats.

## Scoreboard
- Simple but layered: `cache_ref_model` (predictor, byte image) separate from `cache_scoreboard` (comparator). Inputs via `uvm_analysis_imp_decl`.
- Checks: load rdata, rsp id/we echo; after each flush compare mem_model vs ref image.
- Data-only (hit/miss traffic counts printed for info, not failed).
- Failed writeback → those addresses marked unknown, skipped later. Refill error → skip data check.
- Response-timeout (hang) warning.

## Config
- Runtime knobs only (latency, mem ready %, cpu rsp ready %, error %, addr pool, op mix, max_outstanding).
- v2.1: no presets. cache_cfg = default timing; variants cache_cfg_quiet/_bp/_err chosen per test with a factory type override before super.build_phase(). Every test is its own sim from reset; regression = many runs, coverage merged by regression/merge_cov.py from per-run cov_*.csv.

## Assertions
- Reuse existing `cache_ctrl_sva.sv` (ENV_* also checks the TB's drivers). No new SVA file now.

## Tests
smoke, directed (T1–T11), rand, bp, flush, flush_race, err (read+write errors). Basic covergroups: op×hit/miss×victim dirty, wstrb, woff, mem rd/wr×err, backpressure, flush±inv, flush race.

## Coding/comment rules (split version)
- Banner per class: author name/email, what it does, inputs/outputs, "watch out" points.
- Anything non-textbook gets "WHY THIS IS DIFFERENT / OTHER WAY" (e.g. two driver threads, get()/put(), analysis FIFO in sequencer, analysis_imp_decl, response handler for v2).
- Every wait/delay tagged inline: `// WAIT: <what> — <why>` or `// DELAY: <models what>`. Driver/monitor banners have a TIMING section (drive/sample skew, ending handshake, why no race). Clocking blocks explained in cache_if.sv.
- Match RTL style: `_q` suffixes, banner comments.

## v2 (non-blocking) readiness — prepare, do not implement
id in items, split req/rsp threads, max_outstanding knob, blocking lives in the sequence (`get_response`), monitor/scoreboard match by id.
